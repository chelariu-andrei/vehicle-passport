# Onboarding, Car Context and Car Look (mobile) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Add vehicle form with a three-step journey, replace the Ferrari with seven code-built body types the owner can customise, make the whole app follow one active car, and apply the new ground and navigation rules.

**Architecture:** The contract gains `plate` and `appearance` on the vehicle first; the fake API follows, so every behaviour is proven without the backend. The 3D car is `car-kit.js` + `stage.js`, copied from the design system and bundled into the existing WebView page; the same kit draws 2D silhouettes natively. The active car is one local query shared by every tab. The journey and the look editor live in the `vehicle` feature.

**Tech Stack:** Expo SDK 58, expo-router (native tabs), TanStack Query 5, react-hook-form + zod, react-native-svg, react-native-webview, three 0.160 (viewer bundle only), Jest 30 + jest-cucumber + React Native Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-10-onboarding-design.md` ("spec"). Design system: https://claude.ai/artifact/4744YKEHgeUzJgtoCZ3J3Y ("DS"). Read DS files with the Artifact tool: `action: read`, that `url`, `path: project/…`.

## Global Constraints

- Work on branch `feat/onboarding-car-context`. Stage only the paths each task lists. No edits under `server/` or `web/`.
- `contracts/openapi.yaml` changes only in Task 1. Generated files (`schema.d.ts`, `tokens.generated.ts`, `assets/viewer/viewer.html`) are never edited by hand.
- Route files import only from `@/features/*` and `@/shared/*` and hold no logic. A feature imports another only through its `index.ts`. `shared` imports no feature. Allowed feature edges: `vehicle → event`, `scan → vehicle`, `scan → event`, `passport → vehicle`.
- All user-visible strings live in `S/shared/i18n/en.ts`. Copy in the spec's tables is final and verbatim.
- The word "Cancel" appears nowhere in the UI. Back is the app-bar chevron (accessibility label "Back"); no screen has a labelled Back or Cancel button in its content. One primary action per screen, in the bottom bar.
- The plate is never sent anywhere but `updateVehicle`, never logged, never shown on a passport screen.
- No model file, no Draco, no network at viewer runtime. Nothing in the model reads as a real make.
- At most one live WebView stage; list rows and the car list use `CarSilhouette`.
- Body types, palette codes, finishes, wheels, rim colours and tints are exactly the enums in spec §9.
- VIN: `^[A-HJ-NPR-Z0-9]{17}$`, uppercased. Plate: uppercase, `A–Z 0–9 space hyphen`, single spaces, at most 10.
- Touch targets 44pt iOS / 48dp Android. Never `allowFontScaling={false}`. Status never by colour alone. Reduce Motion: no eased turns, no auto-spin, no step slide.
- Query keys: the six existing ones plus `['activeCar', userId]`, `['journeyDraft', userId]`.
- Every commit message ends with `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.

## Plan Decisions (gaps in the spec; reject any at review)

| # | Decision | Why |
|---|---|---|
| D1 | `plate` and `appearance` are optional *and* nullable in `VehicleResponse`; the app treats a missing field as `null` | The backend ships later; today's server omits both |
| D2 | The look model (`Look`, palette, plate rules) lives in `S/shared/viewer/`, not in the `vehicle` feature | `CarViewer` and `CarSilhouette` are shared and may not import a feature |
| D3 | The active car and the journey draft are local queries in the TanStack cache, written through to AsyncStorage per user id | Every tab must re-render on a switch; this is the pattern `useLocalClaims` already uses |
| D4 | `vehicles/new` and `vehicles/[vin]` stay as redirect routes | Existing links and tests keep working |
| D5 | The journey is a stack screen (`R/onboarding/index.tsx`) with its steps as internal state, not one route per step | Step 3 must not be reachable by URL without a car, and Back needs per-step rules |
| D6 | `ConfirmSheet` gains a required `dismissLabel`; each caller names its own quiet action | Spec §7: the quiet action names what leaving means |
| D7 | The grain is a 128px PNG generated by a script with a fixed seed and committed | Deterministic, no new dependency |
| D8 | Car-kit geometry is tested through `bodyGeometry(bodyType)`, a pure export; the three.js assembly is covered by the device gate | Jest has no WebGL or canvas |
| D9 | `PickVehicle` is deleted; with no `vin` param, capture uses the active car | Spec §6 scoping |

## Review Focus

1. **A VIN pasted with spaces, lower case, or I/O/Q** is cleaned to valid characters as typed, and Continue stays disabled until 17 remain. → Task 9.
2. **The active car leaves the account while another tab is open** (transfer approved, 404 `vehicle-not-found`): the next car becomes active, or the empty state shows; no screen keeps showing the lost car. → Task 6 and Task 7.
3. **The WebView never becomes ready** (old Android WebView, WebGL off): step 3 and the home screen stay fully usable on the silhouette, and the look still saves. → Task 5 and Task 11.
4. **"Save this look" fails** (offline, 404): the car is still registered, the message shows, "Skip for now" still finishes the journey. → Task 11.
5. **A plate typed with emoji, lower case, double spaces or 14 characters** is normalised before it is drawn or sent; an empty plate is sent as `null`. → Task 4 and Task 11.
