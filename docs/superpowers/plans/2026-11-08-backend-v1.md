# Backend v1 (vehicle-passport) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `server/` Quarkus backend for the five v1 modules (garage, manual history, invoice scanner, timeline, passport), spec-first: contract and Gherkin before code.

**Architecture:** One Maven module, feature-first hexagonal packages (`vehicle`, `event`, `scan`, `passport`, `shared`). Every feature is specified by `.feature` files that run through Cucumber-JVM on Quarkus against real use cases with fake `port/out` adapters. A smaller `@QuarkusTest` suite covers Postgres, HTTP and auth. ArchUnit enforces the layering.

**Tech Stack:** Java 25, Maven, Quarkus 3.40.1.1, Hibernate ORM Panache, Flyway, Postgres 17 (Supabase), quarkus-oidc, Cucumber via `quarkus-cucumber` 1.3.0, ArchUnit 1.5.1, PDFBox 3.0.8, ZXing 3.5.4, AWS SDK v2 S3.

**Spec:** `docs/superpowers/specs/2026-11-08-backend-design.md` (where §5 and §10/§11 differ, §10/§11 win, as the spec itself states).

**Path shorthand:** `M/` = `server/src/main/java/com/vehiclepassport/server/` · `U/` = `server/src/test/java/com/vehiclepassport/server/` · `I/` = `server/src/integration-test/java/com/vehiclepassport/server/` · `F/` = `server/src/integration-test/resources/features/` · `DB/` = `server/src/main/resources/db/migration/`.

## Global Constraints

- Evidence order: `ESTIMATED < USER_CONFIRMED < DOCUMENTED < VERIFIED`. Manual event → `USER_CONFIRMED`; confirmed scan → `DOCUMENTED`. No v1 flow produces the other two.
- Only the active owner adds/edits/deletes events, scans, creates passports, corrects vehicle data.
- An event is editable only by the owner of the ownership period that created it (§11).
- The passport and timeline never expose owner ids, creator ids, period ids or ownership dates.
- A snapshot never changes after creation. A public link can always be revoked.
- A scanned value is never saved as `DOCUMENTED` without explicit confirmation.
- Odometer contradiction is a hard error on add, edit and scan confirm; total/sum mismatch is only a warning (tolerance 0.01).
- VIN: 17 chars, ISO 3779 charset, no I/O/Q, check digit not enforced.
- Scan files: `image/jpeg`, `image/png`, `application/pdf`, ≤ 10 MB; batch ≤ 20 files.
- Worker: `SELECT … FOR UPDATE SKIP LOCKED`, max 3 attempts, processing timeout returns jobs to PENDING.
- Public token ≥ 128 bits from `SecureRandom`, URL-safe, stored recoverably. Public endpoint returns the same 404 for unknown, revoked and expired.
- Hash: SHA-256 over canonical JSON (UTF-8, sorted keys, no whitespace, ISO-8601 dates, money as 2-decimal strings, nulls omitted, events sorted by date then id).
- Errors: RFC 9457 `application/problem+json` from one mapper in `shared/error`. Foreign vehicle → 404. Prior-period event edit → 403.
- `contracts/openapi.yaml` is the source of truth. Schema changes only through new Flyway migrations; `quarkus.hibernate-orm.schema-management.strategy=none`.
- Layering per `.claude/rules/backend-architecture.md`. Cross-feature calls only through the other feature's `application/port/in`.

## Plan Decisions (gaps the spec leaves open — reject any at review)

| # | Decision | Why |
|---|---|---|
| D1 | Quarkus **3.40.1.1**, not 4.0 | "Latest" read as latest stable; 4.0.0 is at Beta3 |
| D2 | `domain` may import exactly two classes from shared: `shared.error.DomainException`, `shared.error.ErrorKind` (both pure Java) | One central mapper in `shared` cannot know feature exceptions, and `shared` must not depend on features |
| D3 | All tables live in Postgres schema **`vehicle_passport`**, not `public` | Supabase exposes `public` through its REST API with the anon key. The spec does not rely on RLS, so tables in `public` would be a data leak |
| D4 | A `DOCUMENTED` event: only `notes` can be edited; other changes → 422 `documented-event-immutable`. Delete remains allowed | "Events never silently downgrade", and a buyer must be able to trust the level. To fix a bad scan: delete and re-scan |
| D5 | Required: `odometerKm`, `costAmount`, `currency`. Optional: `engine`, `notes`, `details` | The spec marks optional fields with `?`; engine is absent from its own Gherkin example |
| D6 | `parts[].price` is the **line total**; `qty` is informational | Spec's rule is `sum(parts)+labor == total` |
| D7 | Until a provider is chosen, production uses `NoProviderExtractionAdapter`; jobs end `FAILED` | The app must boot with the provider undecided. **The scanner does not work in production until then** |
| D8 | "Cancel in-flight scans when ownership ends" is done by the worker sweep and by confirm/get checks, in new state `CANCELLED` | Avoids `vehicle → scan` dependency and a feature cycle |
| D9 | An owner who regains a car gets a new period; their old events and documents stay locked | Direct reading of §11 |
| D10 | Fuel enum: `PETROL, DIESEL, HYBRID, ELECTRIC, LPG, OTHER`. Year: 1886..current year + 1 | Unspecified |
| D11 | The owner's pending-claim list shows only claim id and filing date | "Without personal data of anyone"; there is no user table |
| D12 | Snapshot stored in a `text` column, not `jsonb` | `jsonb` rewrites key order and whitespace, which would break hash re-verification |
| D13 | One `passport` table holds the link columns; `PublicLink` remains a separate domain type | v1 has exactly one link per passport |
| D14 | "ArchUnit first in CI" is delivered as a Surefire execution that runs before all other tests. No CI workflow is added | No CI host or git remote exists yet |

## Review Focus

1. Two users register the same unowned VIN at the same moment, or two claims are approved at once: exactly one open ownership period must result, and the loser gets a clean 409, not a 500. *(Task 7)*
2. Romanian diacritics (`ă â î ș ț`) in notes or service names, and histories long enough to overflow a page: the PDF must render them all, not crash. *(Task 17)*
3. Supabase-signed tokens that are not a logged-in user (no `sub`, or `aud` other than `authenticated`): must be 401. *(Task 4)*
4. A file whose bytes do not match its declared type, or a hostile client filename such as `../../x.pdf`: rejected with 415, and the name is never used in a storage key. *(Task 12)*
5. Notes with quotes, newlines or emoji surviving storage and JSON serving: the hash recomputed from the served snapshot must still match. *(Task 18)*
